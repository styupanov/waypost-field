# Trip persistence

Waypost-owned trips are stored in four normalized tables: `users`, `trips`,
`trip_versions`, and ordered `trip_stops`. UUIDs are generated by PostgreSQL
with `gen_random_uuid()`; the migration ensures `pgcrypto` is available.

Run local migrations with:

```powershell
npm run db:migrate
```

The command reads `DATABASE_URL` from the untracked `.env.local`, records each
filename and SHA-256 checksum in `waypost_schema_migrations`, and applies a new
migration transactionally. Applied migration files must not be edited.

`createTripWithDraft` creates the trip, draft version 1, ordered stops, and the
current-version link in one transaction. `saveCurrentDraftVersion` updates that
same mutable draft version and replaces its stops transactionally. It refuses
to mutate a version whose state is `finalized`. A future Finalize operation can
freeze the current version; subsequent editing can then create the next draft
version without changing this schema.

Final route geometry is stored as PostGIS `geometry(LineString,4326)`. Every
origin, destination, waypoint, and attraction is stored as
`geometry(Point,4326)`. Known attractions retain both their foreign key and a
small display snapshot. Frontend `user_attraction` maps to persisted
`source=user`; automatic recommendations map to `source=waypost`.

Along-the-Way alternatives are derived recommendations, not owned trip state,
so they are deliberately not persisted and can be recalculated from current
data later.
